# StarService 智能客服平台 — 技术部署与运维手册 v3.2

## 一、部署要求

### 1.1 硬件配置

| 部署规模 | 日对话量 | CPU | 内存 | GPU | 存储 |
|----------|---------|-----|------|-----|------|
| 单机标准版 | < 10万 | 16核 | 32GB | RTX 4090 ×1 | 500GB SSD |
| 集群标准版 | 10-50万 | 32核×3 | 64GB×3 | A100 ×2 | 2TB SSD |
| 集群旗舰版 | > 50万 | 64核×6 | 128GB×6 | A100 ×6 | 10TB SSD |

### 1.2 软件依赖

- 操作系统：Ubuntu 22.04 LTS 或 CentOS 8+
- CUDA 版本：12.1+
- Docker 版本：24.0+
- Kubernetes 版本：1.26+
- Python 版本：3.10+
- Node.js 版本：18+

### 1.3 网络要求

- 对话 API 响应延迟：< 200ms（P99）
- 模型推理延迟：< 500ms（P95）
- WebSocket 连接保活间隔：30s
- 文件上传（知识库文档）最大：50MB
- 单次对话最大 token 数：4096

## 二、安装步骤

### 2.1 快速安装（单机标准版）

```bash
# 1. 拉取安装脚本
wget https://repo.starglow-tech.com/starservice/install.sh
chmod +x install.sh

# 2. 执行安装
sudo ./install.sh --edition standard --license YOUR_LICENSE_KEY

# 3. 启动服务
systemctl start starservice
systemctl status starservice

# 4. 验证部署
curl http://localhost:8080/api/health
```

### 2.2 集群部署

```bash
# 使用 Helm Chart 部署
helm repo add starglow https://charts.starglow-tech.com
helm install starservice starglow/starservice-cluster \
  --set replicas=3 \
  --set gpu.enabled=true \
  --set gpu.count=2 \
  --namespace starservice
```

### 2.3 首次配置

安装完成后需要完成以下初始化配置：
1. 登录管理后台（默认端口 8443）
2. 配置渠道接入：在「渠道管理」中添加微信、网页、APP 等渠道
3. 上传初始知识库：在「知识库管理」中上传 FAQ 和产品文档
4. 配置意图分类：选择行业模板或自定义意图分类模型
5. 创建测试会话验证：使用内置测试工具发送测试消息

## 四、运维监控

### 4.1 关键指标

| 指标 | 告警阈值 | 严重阈值 |
|------|---------|---------|
| 对话响应延迟 P99 | > 300ms | > 500ms |
| 意图识别准确率（24h） | < 95% | < 90% |
| GPU 利用率 | > 90% | > 95% |
| 内存使用率 | > 80% | > 90% |
| 错误率（5xx） | > 0.1% | > 0.5% |
| 知识检索延迟 P99 | > 100ms | > 200ms |

### 4.2 日志管理

日志文件位于 `/var/log/starservice/`：
- `api.log` — API 请求日志
- `model.log` — 模型推理日志
- `error.log` — 错误日志
- `access.log` — 访问日志（Nginx 格式）

日志轮转策略：每天轮转，保留 30 天。

### 4.3 备份策略

- 对话记录：实时写入 PostgreSQL + 每小时增量备份到 OSS
- 知识库索引：每天凌晨 2 点全量备份
- 模型配置：Git 版本管理 + 每周备份到私有仓库
- 用户数据：实时双写 + 异地灾备

## 五、故障排查

### 5.1 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 对话响应超时 | GPU 显存不足 | 降低并发数或扩展 GPU 节点 |
| 意图识别率下降 | 知识库过期 | 更新知识库文档，重新训练意图模型 |
| 知识检索返回空 | 向量索引损坏 | 重建索引：`starservice-cli rebuild-index` |
| WebSocket 频繁断开 | 网络不稳定 | 检查负载均衡配置，启用连接保活 |
| 内存泄漏 | 对话缓存未清理 | 调整 `cache.ttl_seconds` 参数，默认应为 3600 |

### 5.2 紧急回滚步骤

```bash
# 1. 停止当前版本
systemctl stop starservice

# 2. 回滚到上一个稳定版本
starservice-cli rollback --version last-stable

# 3. 验证
starservice-cli health-check

# 4. 恢复流量
systemctl start starservice
```

## 六、性能优化

### 6.1 模型优化

- 使用 FP16 混合精度推理，吞吐量提升 40%
- 启用模型量化（INT8），显存占用降低 50%
- 对话模型批处理大小：标准版 batch_size=8，集群版 batch_size=32
- 意图模型缓存 TTL：300 秒（相同问题复用结果）

### 6.2 知识库优化

- 文档分块大小：推荐 800-1200 字符
- 向量索引类型：HNSW（高召回）或 IVF（高吞吐）
- 热门问题自动缓存到 Redis，命中率预期 > 60%
- 定期清理低频文档（30 天未命中自动归档）

## 七、安全加固

- API 访问必须使用 HTTPS + API Key 认证
- 管理后台支持 IP 白名单和双因素认证
- 敏感信息（手机号、订单号）自动脱敏展示
- SQL 注入防护：所有数据库查询使用参数化
- 定期漏洞扫描：每月执行一次自动化扫描
- DDOS 防护：接入云服务商 WAF
